# Events

This folder defines the event taxonomy used to translate real-world developments into structured inputs.

Use this folder for:
- event classes
- trigger definitions
- severity levels
- normalization rules
- event-to-impact mapping assumptions

## Protective interpretation

Events should not only be classified by category and severity, but also by whether they threaten conditions that are necessary for a good life and continued agency.

This means event descriptions should help answer:
- which life conditions are affected
- whether the event is reversible or risks irreversibility
- whether it can be prevented, mitigated, buffered, transferred, recovered from, or only adapted to
- whether formal coverage differs from real recoverability
- whether the event creates second-order fragility after the initial shock

## Event handling priorities

When events are brought into the pipeline, they should support a protective reading as well as an explanatory one.

In practice this means event inputs should make it easier to identify:
- threshold-relevant events
- catastrophic downside exposure
- buffering options
- transfer mechanisms
- recovery requirements
- adaptation windows
- false-safety risks
