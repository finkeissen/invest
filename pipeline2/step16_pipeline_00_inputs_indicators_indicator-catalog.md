# Indicator Catalog

## Purpose

This file lists the first indicator families that should anchor world-state description in Invest.

The catalog should not only track growth, performance, and directional improvement. It should also track preservation, threshold defense, buffering capacity, and recoverability.

A useful indicator system in Invest must help answer at least four questions:
- what is improving?
- what is degrading?
- what is close to a critical threshold?
- what would still remain recoverable after a shock?

## Family A: Personal vitality indicators

- sleep quality
- resting energy and fatigue profile
- physical capacity
- recovery time
- mental stability
- concentration quality
- addiction risk or dependency markers
- injury exposure or accumulated strain
- burnout proximity
- chronic-condition management stability

## Cross-cutting protective indicator lenses

Any indicator family may also be tagged through the following protective lenses:
- threshold proximity
- irreversibility risk
- buffering capacity
- transfer coverage
- recoverability
- maintenance burden
- adaptation window
- false-safety risk

These lenses matter because formal coverage and real protection are not the same thing. A system can appear covered while remaining brittle, slow to recover, or dependent on support that disappears under stress.

## Data design rule

Each concrete indicator file or dataset should record:
- what the indicator measures
- why it matters
- frequency
- lag structure
- likely source class
- known failure modes
- downstream use
- which life conditions it helps monitor
- whether it signals growth, preservation, threshold defense, or recoverability
- what kind of false reassurance it might create if read too literally

## Warning

Indicators are not reality itself.

Some of the most important human goods are only imperfectly measurable. The model should treat low-measurement domains with humility rather than ignoring them.

This is especially important for protection-oriented indicators. A measured signal of coverage, reserves, or readiness should never be confused with guaranteed resilience in lived conditions.
